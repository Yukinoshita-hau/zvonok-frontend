# Stage 10.1 isolated acceptance

Run only with the reviewed labelled acceptance stack. All URLs and SQL database names are fixed to loopback / `zvonok_stage10_1`; do not point these scripts at another deployment. No new test framework is installed. `common.cjs` uses the already bundled Playwright; override `STAGE10_PLAYWRIGHT` with an existing Playwright module path if necessary.

1. Preserve the current Git patch and source files. Review both backend Stage 6 SQL scripts. Build with JDK 21. Do not run Maven package over a running Windows jar: stop only the verified acceptance backend first, or packaging cannot rename it.
2. Existing `zvonok-stage10-pg` must have label `zvonok.acceptance=stage10` and bind `127.0.0.1:15432`. Inspect before starting it. Never reuse an unknown database. `backend/ops/stage10-1/start.ps1` without `-Resume` creates the *new* `zvonok_stage10_1` and random local credentials; it refuses an existing runtime state. Subsequent backend runs require `-Resume` (`ddl-auto=validate`). It is a foreground process. Credentials stay in ignored `backend/stage10-1-evidence/runtime.env`; never print or publish it.
3. In another terminal run backend `ops/stage10-1/infrastructure.ps1`. It checks existing Stage 10.1 labels, builds actual MinIO from pinned official upstream Go source, and starts MinIO + the pinned LiveKit 1.13.10 image. No host S3 directory is mounted. The old Stage 10 SFU must be stopped after label/purpose verification because its port conflicts. Docker/Go downloads require network access. The MinIO build may take minutes.
4. Start `node scripts/stage10-1/s3-proxy.cjs` from the frontend root. It forwards real S3 traffic from loopback 19000 to 19001; its 19002 control injects method-specific HTTP failures without storing objects. Run the backend with `-Resume -JwtMilliseconds 300000` for storage/chat or `15000` for auth/media expiry checks. Do not change production TTL. Apply the reviewed Stage 6 SQL twice using `psql -v ON_ERROR_STOP=1` inside the labelled PostgreSQL container, explicitly `-d zvonok_stage10_1`.
5. Start Vite with `VITE_API_URL=http://127.0.0.1:18080/api`, `VITE_WS_URL=ws://127.0.0.1:18080/api/ws-raw`, host `127.0.0.1`, port `13000`, strict port. Run `./scripts/stage10-1/run.ps1 -Suite Storage|Auth|Chat|Media` (choose one value). Storage creates its private bucket through authenticated S3; media uses synthetic devices with real SFU/WebRTC. Voice/video upload fixtures use HTTP rather than the product's recording buttons. History fixtures and bulk loading use actual STOMP / Redux HTTP thunks, then `history-ui.cjs` verifies native wheel pagination using the latest isolated history fixture. Initial load is not counted as 620 UI sends.
6. Persistent DELETE-outage acceptance deliberately remains FAIL: cleanup can leave an orphan if every S3 DELETE retry fails. Its diagnostic script saves evidence and manually removes only the just-created SQL-unreferenced test key after resetting the fault. No durable cleanup subsystem is added. Never suppress this result. Keep initial failed runs and successful repeats separately.
7. Run frontend `scripts/stage10-1/regression.ps1` and backend `ops/stage10-1/regression.ps1`. `*IT` owns its Testcontainers PostgreSQL; do not override it with deployment connection settings.
8. Before shutdown run `storage-audit.cjs` and the backend read-only audit SQL against **zvonok_stage10_1**. Reset fault control, close browser contexts, verify no active calls, save evidence. Stop only verified backend/Vite/proxy processes, then `infrastructure.ps1 -Stop` and the labelled acceptance PostgreSQL container. Do not remove unknown containers. MinIO `/data` is tmpfs: stopping discards test objects; preserved DB attachment rows are historical evidence, not a reusable storage backup. Next run must create new fixtures and bucket. Existing test DB and stopped containers remain available for inspection; do not use this lifecycle for real data.

Grace timers remain invitation 60 s, initial connect 120 s, confirmed-empty media grace 90 s, reconciliation interval 30 s. Browser offline and SFU pause do not represent real Wi-Fi/IP/NAT changes. No two-computer hardware acceptance, screen-capture quality, TURN, TLS proxy or production capacity is established here.
